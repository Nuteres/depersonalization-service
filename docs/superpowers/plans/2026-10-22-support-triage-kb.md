# Support Triage Knowledge Base & FAQ in Notion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать в Notion (внутри страницы «Схрон») структурированную базу знаний и FAQ по продукту «Деперсонализация ПД (152-ФЗ)» для использования AI-агентом саппорт-триажа и оператором, а также внедрить утилиту и регламент синхронизации базы при выкатке обновлений.

**Architecture:** 
1. В Notion на странице «Схрон» (`1eb2e673-5a41-8009-91c4-c879ff6fa01b`) создается страница-хаб `🛡️ База знаний: Деперсонализация ПД (152-ФЗ)` с общим руководством по архитектуре и нормативной базе.
2. Внутри хаба создается реляционная база данных (Notion Database) `❓ База знаний и FAQ` со схемой свойств (`Вопрос / Статья`, `Категория`, `Теги / Ключи`, `Аудитория`, `Версия фичи`, `Статус`) и набором структурированных карточек ответов.
3. В репозитории создается Go-утилита `tools/sync_kb/` для программного обновления и дополнения базы знаний из файлов `version.go`, `CHANGELOG.md` и `docs/USER_GUIDE.md`.
4. В правила разработки (`AGENTS.md`) вносится регламент синхронизации базы знаний перед релизом.

**Tech Stack:** Notion API (MCP / REST), Go 1.23, Markdown, GitHub CLI (`gh`).

**Spec:** [`support_triage_kb_design.md`](file:///Users/nuter/.gemini/antigravity/brain/afb20114-82ff-4c96-8811-ea313d07f2b7/support_triage_kb_design.md)

## Global Constraints
- Родительская страница Notion: «Схрон» (`1eb2e673-5a41-8009-91c4-c879ff6fa01b`).
- 100% Air-Gapped требования продукта: в документации и FAQ четко фиксировать отсутствие внешних сетевых вызовов в деперсонализаторе.
- Формат ключей и криптография: AES-256-GCM + PBKDF2 (100k итераций), расширение `.depmap`, маска `0600`.
- Версия продукта: текущая `v1.14.1`.
- Запрет на микро-PR: все изменения ведутся в ветке `feat/support-kb-notion` без преждевременного открытия PR.
