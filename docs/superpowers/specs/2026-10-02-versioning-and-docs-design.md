## 1. Контекст и цели

Проект активно развивается: осуществлен переход на Svelte 5 (Runes), поддержано 8 офисных форматов данных, переработан UI предпросмотра таблиц (интерактивный ресайз колонок, бесконечный скролл), обновлены модальные окна и скорректирована терминология («ключ шифрования» вместо запутанного «ключ целостности (соль)»).

**Цель:**
1. Внедрить легковесную и идиоматичную для Go систему версионирования (SemVer).
2. Зафиксировать единый источник правды для версии приложения, чтобы она автоматически отображалась в графическом интерфейсе и системной информации.
3. Внедрить стандарт ведения `CHANGELOG.md` (Keep a Changelog) и зафиксировать в нем историю изменений для релизов 1.0.0 и 1.1.0.
4. Синхронизировать и поддерживать в актуальном состоянии всю документацию проекта (`README.md`, `docs/USER_GUIDE.md`, `docs/ARCHITECTURE.md`).
5. Зафиксировать обязательные правила проекта в `AGENTS.md`, чтобы агент всегда следовал этим регламентам при любых дальнейших доработках.

## 2. Архитектура системы версионирования

### 2.1 Единый источник правды (Single Source of Truth)
В соответствии с лучшими практиками Go (KISS):
- Создается пакет `internal/version/version.go`:
  ```go
  package version

  // Version — текущая версия приложения согласно Semantic Versioning.
  const Version = "1.1.0"
  ```
- Метод `GetAppInfo()` в `internal/desktop/app.go` возвращает `version.Version`:
  ```go
  func (a *DesktopApp) GetAppInfo() map[string]string {
      return map[string]string{
          "version": "v" + version.Version,
          "os":      detectOS(),
          "arch":    goruntime.GOARCH,
      }
  }
  ```
- В `frontend/package.json` поле `"version"` синхронизируется со значением `"1.1.0"`.
- В шапке интерфейса (`frontend/src/lib/components/layout/Header.svelte`) динамически отображается строка вида `v1.1.0 • macOS (arm64)`.

### 2.2 Правила семантического версионирования (SemVer)
- **PATCH ($X.Y.Z+1$)** — мелкие исправления багов, опечаток, точечные правки стилей CSS, внутренний рефакторинг без изменения функционала и интерфейса.
- **MINOR ($X.Y+1.0$)** — добавление нового функционала, новых форматов файлов, переработка экранов UI, оптимизация производительности, обновление мажорных библиотек (например, Svelte 5). Текущий релиз бампается с `1.0.0` до `1.1.0`.
- **MAJOR ($X+1.0.0$)** — несовместимые изменения формата ключей `.depmap`, кардинальное изменение протоколов или архитектуры приложения, нарушающее обратную совместимость.

## 3. Регламент ведения `CHANGELOG.md`

- Файл создается в корне репозитория: `CHANGELOG.md`.
- Формат: [Keep a Changelog 1.0.0](https://keepachangelog.com/ru/1.0.0/).
- Секции для каждого релиза:
  - `### Добавлено` (новые возможности)
  - `### Изменено` (модификации существующего поведения или UI)
  - `### Исправлено` (багфиксы)
  - `### Удалено` (устаревший код или неактуальные элементы)
- В журнале фиксируются:
  - Релиз `[1.1.0] - 2026-10-02` (масштабный релиз со Svelte 5, ресайзом колонок, бесконечным скроллом, очисткой модалок и исправлением терминологии).
  - Релиз `[1.0.0] - 2026-09-30` (базовый начальный релиз).

## 4. Синхронизация документации

При бампе версии обязательно актуализируются:
1. `docs/USER_GUIDE.md`:
   - Замена термина «ключ целостности (соль хеширования)» на «ключ шифрования».
   - Описание интерактивного изменения ширины колонок в таблице (drag ресайзера).
   - Описание динамической бесконечной подгрузки строк в окне предпросмотра.
   - Описание нового диалога успешного завершения деперсонализации и восстановления с кнопками копирования путей.
2. `docs/ARCHITECTURE.md`:
   - Описание Svelte 5 Runes (`$state`, `$state.raw`, `$derived`, `$effect`).
   - Описание логики расчета ширин колонок и ресайзеров (`tableState.columnWidths`).
   - Описание подсистемы версионирования (`internal/version`).
3. `README.md`:
   - Обновление бейджей и номеров версий.
   - Ссылка на `CHANGELOG.md`.

## 5. Проектные инструкции `AGENTS.md`

В корне репозитория создается `AGENTS.md` с постоянными правилами для AI-ассистента:
- Всегда следовать SemVer при внесении изменений.
- Всегда добавлять запись в `CHANGELOG.md` при выпуске правок.
- Всегда поддерживать синхронность документации (`USER_GUIDE.md`, `ARCHITECTURE.md`, `README.md`).
- Сохранять полную автономность (100% Air-Gapped, все зависимости в `vendor/`, никаких внешних сетевых вызовов).
- Проверять работоспособность тестами `go test ./...` и `npm --prefix frontend run check`.
