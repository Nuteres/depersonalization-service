# Спецификация: Обратная персонализация (деобезличивание) через зашифрованные файлы-ключи .depmap

## 1. Введение и бизнес-контекст

В соответствии с требованиями 152-ФЗ и Приказа Роскомнадзора от 05.09.2013 № 996 (п. 4 «Метод введения идентификаторов»), оператор персональных данных вправе осуществлять деперсонализацию данных с возможностью их последующего восстановления в доверенном контуре.

### Сценарий использования (User Flow):
1. **Этап 1: Обезличивание с фиксацией ключа:**
   - Пользователь загружает исходный файл (`clients.xlsx`).
   - Выбирает колонки для очистки (ФИО, СНИЛС, паспорт, телефон и др.).
   - При сохранении очищенного файла ставит галочку `[✔] Создать ключ восстановления (.depmap)` (опционально задаёт пароль).
   - Программа сохраняет `clients_anonymized.xlsx` и защищённый файл `clients_anonymized.xlsx.depmap`.
2. **Этап 2: Внешняя обработка:**
   - Очищенный файл `clients_anonymized.xlsx` передаётся внешним подрядчикам, аналитикам, ML-разработчикам.
   - Файл-ключ `.depmap` остаётся строго внутри закрытого контура организации.
   - Подрядчики проводят анализ, рассчитывают скоринг, добавляют новые колонки и возвращают результат: `clients_processed.xlsx`.
3. **Этап 3: Обратное восстановление (Деобезличивание):**
   - Пользователь открывает вкладку «Восстановление данных».
   - Выбирает возвращённый файл `clients_processed.xlsx`.
   - Указывает сохранённый файл-ключ `clients_anonymized.xlsx.depmap` и вводит пароль (если задавался).
   - Нажимает «Восстановить исходные данные».
   - Программа заменяет синтетические значения на исходные реальные ПДн, сохраняя все новые колонки, добавленные подрядчиками.

## 2. Криптографический формат файла-ключа (.depmap)

Файл `.depmap` представляет собой защищённый бинарный контейнер с аутентифицированным шифрованием AES-256-GCM:

### Структура бинарного файла:
```
+---------------------------------------------------------------+
| Magic Header: "DEPMAP01" (8 байт ASCII)                       |
+---------------------------------------------------------------+
| KDF Salt: 16 случайных байт (crypto/rand)                     |
+---------------------------------------------------------------+
| Nonce (IV): 12 случайных байт (crypto/rand)                   |
+---------------------------------------------------------------+
| Ciphertext + GCM Tag (16 байт):                               |
|   Зашифрованный zlib-сжатый JSON со словарём соответствий     |
+---------------------------------------------------------------+
```

### Алгоритм формирования ключа:
* **KDF:** PBKDF2-HMAC-SHA256 (100 000 итераций).
* **Секрет:** пароль пользователя, либо системный мастер-секрет (если пароль не задан).
* **Шифрование:** AES-256-GCM. Обеспечивает строгую целостность и аутентичность. Попытка открыть файл с неверным паролем или повреждёнными байтами немедленно отклоняется с ошибкой аутентификации GCM.
* **Сжатие:** zlib (уровень 6) перед шифрованием — уменьшает размер ключа в 4-8 раз.

### Внутренняя структура данных (JSON):
```json
{
  "version": 1,
  "createdAt": "2026-09-30T12:00:00Z",
  "originalFileName": "clients.xlsx",
  "recordsCount": 1500,
  "mapping": {
    "Смирнов Алексей Петрович": "Иванов Иван Иванович",
    "452-190-883 12": "112-233-445 95",
    "4522 981240": "4510 123890",
    "+7 (912) 345-67-89": "+7 (999) 111-22-33"
  }
}
```

## 3. Архитектура компонентов

### 3.1. Пакет `pkg/depmap`
* `type DepMap struct`: хранение карты соответствий, метаданных и статистики.
* `func NewDepMap(originalFileName string) *DepMap`
* `func (dm *DepMap) Put(synthetic, original string)`
* `func (dm *DepMap) SaveFile(path string, password string) error`
* `func LoadFile(path string, password string) (*DepMap, error)`
* `func InspectHeader(path string) (*HeaderInfo, error)`: чтение сигнатуры и валидность без полной дешифрации.

### 3.2. Пакет `pkg/formats` (Рестореры)
* `func RestoreCSV(ctx context.Context, r io.Reader, w io.Writer, dm *depmap.DepMap) (int, error)`:
  Потоковое чтение CSV, замена синтетических значений из `dm.Mapping[val]`, запись в `w`.
* `func RestoreExcel(ctx context.Context, inputPath, outputPath string, dm *depmap.DepMap, onProgress func(pct int, proc, total int)) (int, error)`:
  Потоковая/построчная замена в листах книги XLSX через `excelize`, сохранение в `outputPath`.

### 3.3. Бэкенд Wails (`cmd/app/wails_app.go`)
* Обновление `ProcessFileTo`:
  * Добавление флагов `createKey bool, keyPassword string, keyPath string`.
  * При обработке: регистрация пар `(synthetic, original)`.
  * При завершении: сохранение файла `.depmap`.
* Новые методы для фронтенда:
  * `SelectKeyFile() (string, error)`
  * `SaveKeyFileDialog(defaultName string) (string, error)`
  * `InspectKeyFile(keyPath string, password string) (*KeyFileInfo, error)`
  * `RestoreFileTo(inputPath string, keyPath string, password string, destPath string) (*RestoreResult, error)`

### 3.4. Фронтенд (`frontend/index.html`)
* **Вкладки режима:**
  * `[ Обезличивание данных ]` | `[ Восстановление данных ]`
* **Окно сохранения при обезличивании:**
  * Чекбокс: `[✔] Создать защищённый ключ восстановления (.depmap)`
  * Опциональное поле пароля.
  * После сохранения: карточка с путями к двум файлам и кнопкой «Показать в папке».
* **Экран восстановления:**
  * Карточка выбора очищенного файла данных (`.xlsx`, `.csv`).
  * Карточка выбора файла-ключа (`.depmap`).
  * Поле ввода пароля (если задан).
  * Кнопка `[ 🔓 Восстановить исходные данные... ]`.
  * Модальное окно прогресса и успеха с указанием сохранённого пути.

## 4. Ограничения и гарантии безопасности
* Автономность: 0 сетевых запросов (Air-Gapped).
* Чистый Go: стандартная библиотека `crypto/*` + `compress/zlib`.
* Защита от утечек: без правильного пароля или файла-ключа восстановить данные математически невозможно (стойкость AES-256).
