**Дата:** 2026-10-15  
**Статус:** Согласовано

## 1. Контекст и цели (Intent & Why)

### Проблема
Пользователи приложения работают на экранах с разным разрешением и плотностью пикселей (от стандартных ноутбуков до 4K-мониторов). Часть пользователей имеют особенности зрения и испытывают сложности при чтении мелкого шрифта в предпросмотре таблиц, текстовых документов и PDF. Ранее отсутствовал централизованный, кроссплатформенный механизм регулировки масштаба интерфейса с визуальным управлением и поддержкой привычных жестов мыши и клавиатуры.

### Цели
1. Обеспечить возможность плавного и дискретного масштабирования всего интерфейса приложения в диапазоне от **70%** до **200%**.
2. Реализовать управление масштабом через:
   - **Колёсико мыши**: `Ctrl + Wheel` (Windows/Linux) и `Cmd + Wheel` (macOS).
   - **Горячие клавиши**: `Ctrl/Cmd + Plus` / `=`, `Ctrl/Cmd + Minus`, `Ctrl/Cmd + 0` (сброс к 100%).
   - **Интерактивный блок в шапке**: кнопки `–`, процентный бейдж `100%` (сброс по клику), `+`.
3. Сохранять выбранный пользователем масштаб в `localStorage`, чтобы при перезапуске приложения интерфейс открывался в комфортном для пользователя размере.
4. При масштабировании жестами/клавиатурой показывать кратковременный визуальный бейдж текущего процента.
5. Обеспечить 100% работоспособность на всех целевых платформах: macOS (WebKit / WKWebView), Windows (WebView2), Alt Linux (WebKitGTK).

### Не-цели (Non-goals)
- Раздельное независимое масштабирование отдельных модальных окон или секций (масштабирование действует глобально на всё окно приложения для целостности UX).
- Изменение физических размеров внешнего окна операционной системы (Wails Window Size).

### Анти-цели (Anti-goals)
- Размытие шрифтов (растеризация векторов/SVG/текста при увеличении).
- Поломка системных координат (hit-testing при нативном Drag & Drop файлов через Wails, всплывающие окна и тултипы).
- Подключение внешних библиотек или сетевых ресурсов (строгое соблюдение 100% Air-Gapped).

## 2. Архитектура решения

### 2.1. Реактивное состояние: `zoomState.svelte.ts`
Создаётся изолированное реактивное хранилище состояния на базе Svelte 5 runes:
```typescript
class ZoomState {
  currentZoom = $state<number>(1.0); // 1.0 = 100%
  showIndicator = $state<boolean>(false);
  indicatorTimeout: number | null = null;

  readonly minZoom = 0.70;
  readonly maxZoom = 2.00;
  readonly stepButtons = 0.10; // Шаг для кнопок: 10%
  readonly stepWheel = 0.05;   // Шаг для колёсика: 5%

  init(): void;
  zoomIn(step?: number): void;
  zoomOut(step?: number): void;
  resetZoom(): void;
  setZoom(value: number): void;
  private applyZoom(): void;
  private showTransientIndicator(): void;
}

export const zoomState = new ZoomState();
```

### 2.2. Механизм применения масштаба
Для сред Wails v2 (WebKit / Blink / Chromium WebView2) свойство CSS `zoom` на элементе корневого документа (`document.documentElement.style.zoom = String(zoom)`) является нативным, аппаратным и обеспечивает:
- Пересчет размеров шрифтов, паддингов, отступов и сетки Tailwind без смещения осей;
- Сохранение векторной четкости шрифтов и SVG-иконок;
- Корректную работу скроллбаров и позиционирования `fixed`/`absolute`.

### 2.3. Обработка событий (Wheel & Keydown)
В `App.svelte` на уровне `window` регистрируются обработчики:
1. **Колёсико мыши (`wheel`)**:
   - Проверяется условие `e.ctrlKey || e.metaKey`.
   - Если зажат Ctrl/Cmd: вызывается `e.preventDefault()` (для подавления нежелательной вертикальной прокрутки контейнера).
   - При `deltaY < 0`: приближение (+5%).
   - При `deltaY > 0`: отдаление (-5%).
   - Вызывается отображение кратковременного бейджа масштаба.
2. **Горячие клавиши (`keydown`)**:
   - `Ctrl/Cmd` + `Equal` (`=`) или `NumpadAdd`: увеличение (+10%).
   - `Ctrl/Cmd` + `Minus` (`-`) или `NumpadSubtract`: уменьшение (-10%).
   - `Ctrl/Cmd` + `Digit0` (`0`) или `Numpad0`: сброс в 100%.
   - `e.preventDefault()` для предотвращения браузерных перехватов.

### 2.4. Интерфейс: блок управления в `Header.svelte`
В правой части шапки рядом с кнопкой «Журнал» размещается компактная панель:
```html
<div class="flex items-center bg-[#F0EFEB] p-1 text-xs font-medium border border-[#E8E7E3]">
  <button
    type="button"
    onclick={() => zoomState.zoomOut()}
    class="px-2 py-1 text-[#78716C] hover:text-[#1C1917] hover:bg-white transition cursor-pointer"
    title="Уменьшить масштаб (Ctrl + -)"
  >
    –
  </button>
  <button
    type="button"
    onclick={() => zoomState.resetZoom()}
    class="px-2.5 py-1 font-mono text-[11px] text-[#1C1917] hover:bg-white transition cursor-pointer"
    title="Сбросить масштаб (Ctrl + 0)"
  >
    {Math.round(zoomState.currentZoom * 100)}%
  </button>
  <button
    type="button"
    onclick={() => zoomState.zoomIn()}
    class="px-2 py-1 text-[#78716C] hover:text-[#1C1917] hover:bg-white transition cursor-pointer"
    title="Увеличить масштаб (Ctrl + +)"
  >
    +
  </button>
</div>
```

### 2.5. Всплывающий индикатор масштабирования
При изменении масштаба через горячие клавиши или колёсико мыши по центру экрана на 1.2 секунды плавно появляется бейдж:
`Масштаб: 125%` с анимацией затухания, информирующий пользователя об актуальном значении.

## 3. Влияние на систему и безопасность

1. **Air-Gapped**: Не требует сетевых соединений.
2. **Персистентность**: Ключ `localStorage['dep_app_zoom']` валидируется при загрузке: если значение вне диапазона [0.7, 2.0] или повреждено, сбрасывается на 1.0.
3. **Совместимость с Drag & Drop**: Координаты `OnFileDrop` передаются из бэкенда в пикселях окна; функция `document.elementFromPoint(x, y)` в `App.svelte` работает корректно с зумированным DOM.
