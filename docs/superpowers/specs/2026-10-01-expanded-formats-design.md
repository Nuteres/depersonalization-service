# Архитектурная спецификация: Расширение поддерживаемых форматов файлов (.xlsb, .ods, .xls, .docx, .odt)

**Дата:** 2026-10-01  
**Статус:** Утверждено пользователем  
**Область:** `pkg/formats`, `cmd/app`, `frontend`  
**Целевые платформы:** Alt Linux 10.4 (p10, x86_64), Windows 10/11 (x86_64), macOS (Apple Silicon + Intel x86_64)

---

## 1. Введение и цели

Приложение для деперсонализации данных в соответствии с 152-ФЗ расширяет спектр поддерживаемых форматов для обеспечения бесшовной работы в корпоративных средах, на рабочих станциях отечественной ОС **Альт Линукс** (с пакетами OpenOffice / LibreOffice), а также с наследуемыми и бинарными форматами Microsoft Office.

### Целевые форматы
1. **Электронные таблицы**:
   * **`.xlsx`**: Microsoft Excel 2007+ OpenXML (уже реализовано).
   * **`.ods`**: OpenDocument Spreadsheet — стандартный формат LibreOffice Calc и OpenOffice на Альт Линукс (ГОСТ Р ИСО/МЭК 26300-2010).
   * **`.xlsb`**: Microsoft Excel Binary Workbook — бинарный контейнер BIFF12 для больших объёмов данных.
   * **`.xls`**: Microsoft Excel 97–2003 BIFF8 — устаревший бинарный формат.
   * **`.csv` / `.tsv`**: Текстовые таблицы с разделителями (уже реализовано).
2. **Текстовые документы**:
   * **`.docx`**: Microsoft Word 2007+ OpenXML.
   * **`.odt`**: OpenDocument Text — стандартный формат LibreOffice Writer и OpenOffice на Альт Линукс.
3. **Фиксированные документы**:
   * **`.pdf`**: Физическое безвозвратное закрашивание (Blackout redaction) (уже реализовано).

## 2. Глобальные ограничения и принципы

1. **Air-Gapped / 100% Автономность**:
   * Никаких внешних сетевых вызовов при сборке и в рантайме.
   * Никаких внешних системных зависимостей (не требуется установленный LibreOffice, Python, Java или CGO-библиотеки).
2. **Чистый Go (Pure Go)**:
   * Все новые парсеры и генераторы компилируются статически в единый бинарный файл приложения.
3. **Сохранность разметки и оформления**:
   * В текстовых документах (`.docx`, `.odt`) и таблицах (`.ods`) шрифты, стили, таблицы, изображения, поля, колонтитулы и формулы сохраняются неизменными. Изменяются исключительно текстовые значения выявленных ПДн.
4. **Двусторонняя обратимость (.depmap)**:
   * Все поддерживаемые структурированные форматы (`.xlsx`, `.ods`, `.docx`, `.odt`, `.csv`, `.xls`, `.xlsb`) поддерживают генерацию зашифрованного ключа деперсонализации `.depmap` (AES-256-GCM + PBKDF2).
   * С помощью ключа и исходного пароля файл может быть восстановлен 1-в-1 в исходный вид (`RestoreFileTo`).
5. **Выбор формата сохранения**:
   * Для `.ods`: сохранение в `.ods`, `.xlsx` или `.csv`.
   * Для `.xlsx`: сохранение в `.xlsx` или `.csv`.
   * Для бинарных `.xls` и `.xlsb`: сохранение выполняется в современный `.xlsx` (без ограничений в 65k строк и с максимальной совместимостью).
   * Для `.docx`: сохранение в `.docx` (или `.odt`).
   * Для `.odt`: сохранение в `.odt` (или `.docx`).

## 4. Спецификация модулей

### 4.1. Модуль электронных таблиц (`pkg/formats/`)

#### 1. `ods_handler.go` и `restore_ods.go`:
* **Чтение**: Распаковка `content.xml` из ODS-контейнера через `archive/zip`.
* Парсинг структуры `<table:table>`, `<table:table-row>`, `<table:table-cell>`, `<text:p>`.
* Определение типов колонок (ФИО, СНИЛС, ИНН, Паспорт, Телефон, Карта, Дата) с учетом заголовков и валидаторов.
* **Запись**: Потоковая перезапись текста ячеек с сохранением всех атрибутов стилей (`table:style-name`), типов значений (`office:value-type`) и структуры листа.
* **Восстановление**: Обработка `.depmap` и подстановка оригинальных значений в `<text:p>`.

#### 2. `xlsb_handler.go`:
* **Чтение**: Использование библиотеки `github.com/TsubasaBE/go-xlsb` для чтения листов, строк и значений ячеек в бинарном формате Excel.
* **Преобразование**: Передача строк через `anonymizer.Anonymizer`, генерация маппинга `.depmap`.
* **Запись**: Создание файла через `excelize.NewFile()` и сохранение в современном формате `.xlsx`.

#### 3. `xls_handler.go`:
* **Чтение**: Использование библиотеки `github.com/extrame/xls` для разбора OLE2 Compound File Binary и потоков BIFF8.
* **Преобразование**: Чтение листов, распознавание колонок и значений.
* **Запись**: Сохранение обезличенного результата в формат `.xlsx`.

---

### 4.2. Модуль текстовых документов (`pkg/formats/`)

#### 1. `docx_handler.go` и `restore_docx.go`:
* **Структура**: Архивы `.docx` содержат `word/document.xml`, `word/header*.xml`, `word/footer*.xml`.
* **Обработка разрыва текста (Run-splitting)**:
  * Текст абзаца `<w:p>` формируется из нескольких соседних текстовых узлов `<w:t>`.
  * Алгоритм:
    1. Для каждого абзаца `<w:p>` извлекаются все дочерние `<w:t>` и объединяются в полный текст с сохранением смещений (offsets).
    2. По полному тексту выполняется поиск сущностей ПДн (регулярные выражения + контрольные суммы СНИЛС/ИНН/паспорта/телефоны/ФИО/карты).
    3. Для найденных совпадений генерируются деперсонализированные токены через `Anonymizer`.
    4. Замены проецируются обратно на соответствующие узлы `<w:t>`. Если совпадение пересекает границу между узлами, первый узел получает заменяющее значение, а последующие узлы совпадения очищаются, сохраняя XML-структуру и атрибуты стилей.
* **Вложенные таблицы**: Обработка ячеек `<w:tc>` аналогична обработке абзацев.
* **Восстановление (`restore_docx.go`)**:
  * Сканирование текстовых узлов, сопоставление со словарем замен `depmap.DepMap` и обратная замена синтетических значений на оригинальные.

#### 2. `odt_handler.go` и `restore_odt.go`:
* **Структура**: Текст находится в `content.xml` внутри `<text:p>`, `<text:span>` и `<table:table>`.
* **Алгоритм**:
  * Сбор полного текста абзаца из тегов `<text:span>` и текстовых узлов.
  * Детекция сущностей ПДн.
  * Проекция замен на XML-элементы.
  * Запись обновленного `content.xml` в результирующий ODT-контейнер (все остальные файлы архива копируются байт-в-байт).
* **Восстановление (`restore_odt.go`)**:
  * Подстановка оригинальных значений из ключа `.depmap` в узлы `content.xml`.

### 4.3. Бэкенд Wails (`cmd/app/wails_app.go`)

1. **Расширенные структуры**:
   * `FileInfo`:
     * `FileType string` (`"spreadsheet"`, `"text"`, `"pdf"`)
     * `Format string` (`"xlsx"`, `"xlsb"`, `"ods"`, `"xls"`, `"csv"`, `"docx"`, `"odt"`, `"pdf"`)
     * `Sheets []SheetInfo` (для таблиц)
     * `Entities []EntityInfo` (для всех форматов)
     * `TextSnippets []TextSnippet` (для текстовых документов и PDF)
     * `SupportedExportFormats []string` (список допустимых форматов сохранения)
2. **Метод `InspectFile(path string) (*FileInfo, error)`**:
   * Маршрутизация по расширению файла.
   * Для таблиц: вызов соответствующего инспектора (XLSX, ODS, XLS, XLSB, CSV).
   * Для текстов: вызов `inspectDOCX` / `inspectODT` с подсчётом сущностей и формированием фрагментов предпросмотра До/После.
3. **Метод `ProcessFileTo(...)`**:
   * Поддержка параметров:
     * `OutputPath string`
     * `ExportFormat string` (позволяет сменить формат: например, `.ods` -> `.xlsx`)
     * `DisabledColumnsBySheet map[string][]string` (для таблиц)
     * `DisabledEntityTypes []string` (для текстов: например, отключение замены дат)
     * `GenerateKey bool`, `KeyPassword string`
4. **Метод `RestoreFileTo(inputPath, keyPath, password, destPath string)`**:
   * Автоматическое определение формата файла и вызов соответствующего восстановителя (`RestoreExcel`, `RestoreCSV`, `RestoreODS`, `RestoreDOCX`, `RestoreODT`).

### 4.4. Пользовательский интерфейс (`frontend/`)

1. **Диалог выбора файла**:
   * Поддержка выбора:
     * Таблицы: `*.xlsx;*.xlsb;*.ods;*.xls;*.csv;*.tsv`
     * Тексты: `*.docx;*.odt`
     * PDF: `*.pdf`
2. **Адаптивный экран деперсонализации**:
   * Если `fileType === 'spreadsheet'`: отображаются вкладки листов, таблица, бейджи и чекбоксы отключения колонок.
   * Если `fileType === 'text'`: отображается карточка документа, переключатели категорий ПДн (ФИО, Телефоны, Паспорта, СНИЛС, Карты, Даты), список сниппетов контекста До / После.
   * Если `fileType === 'pdf'`: отображается карточка PDF с информацией о закрашивании и текстовые фрагменты.
3. **Модальное окно сохранения**:
   * Селектор целевого формата файла:
     * Исходный `.ods` -> Выбор: `ODS (.ods)`, `Excel (.xlsx)`, `CSV (.csv)`.
     * Исходный `.xlsx` -> Выбор: `Excel (.xlsx)`, `CSV (.csv)`.
     * Исходный `.xls` / `.xlsb` -> Зафиксировано: `Excel (.xlsx)` с бейджем «Рекомендуемый современный формат».
     * Исходный `.docx` -> Выбор: `Word (.docx)`, `OpenOffice Writer (.odt)`.
     * Исходный `.odt` -> Выбор: `OpenOffice Writer (.odt)`, `Word (.docx)`.
   * Блок генерации ключа `.depmap` с опциональным паролем.
