# Спецификация: Приложение автоматической деперсонализации данных и файлов (152-ФЗ РФ)

- **Дата разработки**: 2026-09-29
- **Статус**: Утверждено (Approved)
- **Целевая аудитория**: Аналитики данных, разработчики, сотрудники служб безопасности, бухгалтерия и кадры
- **Целевые платформы**: **Alt Linux 10.4 (p10, x86_64)**, **Windows 10/11 (x86_64)**, **macOS (Universal Binary: Apple Silicon + Intel)**
- **Формат поставки**: Автономный однофайловый бинарный исполняемый файл с GUI

---

## 1. Цели и назначение продукта

Создание легковесного, высокопроизводительного локального десктопного приложения для автоматического обнаружения и деперсонализации (обезличивания) персональных данных (ПДн) в таблицах и документах в соответствии с требованиями законодательства РФ (Федеральный закон № 152-ФЗ «О персональных данных», Приказ Роскомнадзора от 05.09.2013 № 996).

### Ключевые требования:
1. **100% On-Premise / Air-gapped**: Данные не покидают компьютер пользователя. Запрещены любые внешние сетевые соединения и внешние CDN.
2. **Гарантированная работа на Alt Linux 10.4**: Нативная сборка, совместимая с glibc 2.32 и графическим стеком отечественного дистрибутива.
3. **Единый бинарник**: Никаких интерпретаторов Python, виртуальных окружений или сложных инсталляторов. Запуск двойным кликом.
4. **Простой и чистый светлый интерфейс**: Лаконичный дизайн без перегруженных таблиц и технического шума, понятный любому сотруднику.
5. **Сохранение ссылочной целостности**: Детерминированная псевдонимизация гарантирует, что один и тот же человек во всех выгрузках заменяется на одинаковый синтетический профиль.

## 2. Технологический стек

- **Ядро (Backend)**: **Go 1.22+**
  - Модульная архитектура плагинов-форматов через интерфейс `FormatHandler`.
  - Потоковое чтение и запись Excel: `github.com/xuri/excelize/v2` (StreamWriter / streaming row iterator).
  - Потоковый CSV/TSV: стандартная библиотека `encoding/csv` с буферизацией `bufio`.
  - Потоковый JSON: `encoding/json` / `gjson`.
  - Документы PDF: текстовый синтаксический анализ, определение координат (bounding boxes) и векторное наложение непрозрачных черных рамок (Blackout Redaction) с физическим вырезанием символов из контентного потока.
- **Интерфейс (GUI Layer)**: **Wails v2/v3**
  - Нативный системный WebView (WebKitGTK в Alt Linux, WebView2 в Windows, WebKit в macOS).
  - Внутренний IPC-мост между Go и JavaScript без открытия внешних портов в сеть.
- **Фронтенд**: Чистый, легковесный HTML5, CSS и JavaScript.
  - Все шрифты (**Plus Jakarta Sans**, **JetBrains Mono**) и иконки зашиты внутрь бинарника через директиву `//go:embed`.

## 3. Дизайн-система и пользовательский опыт (UX/UI)

Интерфейс спроектирован по принципам **frontend-design** с акцентом на спокойную предметную эстетику и максимальную ясность.

- **Палитра**:
  - Основной фон окна: `#FBFBFA` (оттенок архивной бумаги).
  - Поверхности карточек: `#FFFFFF` с тонкими графитовыми границами `#E8E7E3`.
  - Типографика: `#1C1917` (глубокие чернила), вспомогательный `#78716C`.
  - Черные плашки цензурирования: `#18181B`.
  - Акценты безопасности: `#065F46` / `#ECFDF5`.
- **Типографика**:
  - Заголовки и интерфейс: **Plus Jakarta Sans** (плотный кернинг, четкая иерархия).
  - Коды, идентификаторы, СНИЛС, таблицы: **JetBrains Mono**.
- **Ключевые экраны и элементы**:
  1. **Карточки распознанных категорий**: вместо хаотичных выпадающих списков над каждой ячейкой система группирует найденные поля в понятные карточки («ФИО Клиента ➜ Заменено на синтетику», «СНИЛС ➜ Валидный модуль 101»).
  2. **Интерактивный переключатель «Очищенные данные ⟷ Исходные с ПДн»**: моментальная визуальная сверка изменений перед сохранением.
  3. **PDF-просмотрщик**: наглядная визуализация страницы с аккуратными чёрными рамками `[ ФИО СКРЫТО ]`, `[ СНИЛС ]`.
  4. **Единая кнопка действия**: «Скачать чистый файл (.xlsx / .pdf)».

## 4. Каталог категорий ПДн и алгоритмы деперсонализации (152-ФЗ РФ)

| Категория ПДн | Паттерн / Распознавание | Алгоритм обезличивания / замены |
| :--- | :--- | :--- |
| **ФИО (Фамилия, Имя, Отчество)** | Анализ заголовков (`фио`, `клиент`, `сотрудник`) + встроенные словари фамилий/имен РФ | Детерминированная замена на реальные русские имена с **автоопределением и сохранением пола** (женские ФИО заменяются только на женские). |
| **СНИЛС** | Формат `XXX-XXX-XXX XX` или 11 цифр подряд | Генерация случайных первых 9 цифр и расчет контрольного числа по официальному **модулю 101** (взвешенная сумма). |
| **ИНН физлица** | 12 цифр | Первые 4 цифры — реальный код региона ФНС РФ, 11-й и 12-й знаки рассчитываются по двум официальным контрольным суммам ФНС. |
| **Паспорт гражданина РФ** | Формат `XX XX XXXXXX` (серия и номер), кем выдан, код подразделения | Генерация валидной серии (коды регионов ОКАТО) + случайный 6-значный номер. Замена «Кем выдан» на стандартный шаблон МВД и псевдонимный код подразделения `XXX-XXX`. |
| **Номера телефонов РФ** | Префиксы `+7`, `8`, скобки, дефисы | Детерминированная замена на валидные мобильные префиксы РФ (`+7 9xx xxx-xx-xx`) либо маскирование `+7 (9**) ***-**-12`. |
| **Электронная почта** | Стандартный Email regex | Генерация синтетического адреса `user_<hash>@example.com` или сохранение домена организации с заменой имени. |
| **Адреса регистрации и проживания** | Распознавание городов, улиц, индексов РФ | Замена на синтетические адреса из встроенного справочника (популярные города и улицы РФ) либо обобщение до субъекта РФ. |
| **Дата рождения / Возраст** | Даты в форматах DD.MM.YYYY, YYYY-MM-DD | **Зашумление со сдвигом**: смещение даты на случайные $\pm N$ дней с сохранением года и возрастной группы, либо обобщение до года рождения. |
| **Банковские карты (МИР, Visa, MC)** | 16 цифр, проверка бинов `2200...` (МИР) | Генерация валидного номера с обязательным расчетом **контрольной суммы по алгоритму Луна (Luhn algorithm)**. |
| **Расчетные счета физлиц** | 20 цифр, начинаются на `40817...` | Генерация валидного счета физлица-резидента РФ. |
| **Водительское удостоверение (ВУ)** | 10 знаков (`XX XX XXXXXX`) | Генерация серии и номера по стандарту ГИБДД РФ. |
| **Госномер автомобиля РФ** | Формат `[А-Я]\d{3}[А-Я]{2} \d{2,3}` | Генерация по ГОСТ РФ с валидными разрешенными буквами кириллицы. |
| **PDF: подписи и фото** | Векторные блоки и изображения в зонах подписей | Наложение физической непрозрачной черной рамки (Blackout). |

## 5. Механизм детерминированности (Сохранение связей)

Для сохранения связей между таблицами используется схема криптографического псевдонимирования:
$$\text{Seed} = \text{HMAC-SHA256}(\text{Исходное значение}, \text{Секретная соль})$$
1. Секретная соль генерируется случайно на сессию либо задается пользователем в настройках.
2. Одинаковые исходные значения дают строго одинаковый `Seed`, гарантируя, что во всех файлах Иванов заменяется на одного и того же Петрова.
3. Без знания секретной соли обратное восстановление исходных ПДн математически невозможно (полное соответствие ст. 3 152-ФЗ об обезличивании).

## 6. Архитектура сборки однофайлового бинарника

### 1. Alt Linux 10.4 (p10, x86_64)
- **Сборочное окружение**: Официальный Docker-образ `registry.altlinux.org/alt/p10`.
- **Зависимости**: `libwebkit2gtk-4.0` / `libwebkit2gtk-4.1`, `glibc 2.32`.
- **Выходные артефакты**:
  - `depersonalizer-altlinux-amd64` (автономный ELF-файл, запуск из любой папки).
  - `depersonalizer-1.0.0-alt1.x86_64.rpm` (пакет для `apt-rpm`).

### 2. Windows 10/11 (x86_64)
- **Сборочное окружение**: Кросс-компиляция через `mingw-w64` или нативный Windows runner.
- **Рантайм**: Системный `WebView2`.
- **Выходной артефакт**: `depersonalizer-windows-amd64.exe` (портативный, без прав администратора).

### 3. macOS (Apple Silicon + Intel)
- **Сборочное окружение**: macOS runner с `lipo`.
- **Рантайм**: Системный `WebKit`.
- **Выходной артефакт**: `Деперсонализатор.app` и `.dmg` образ.
