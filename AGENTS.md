# Инструкции и правила проекта для AI-ассистентов (AGENTS.md)

В данном репозитории разрабатывается кроссплатформенное приложение деперсонализации и обратного восстановления персональных данных (152-ФЗ РФ, Приказ Роскомнадзора от 19.06.2025 № 140) на базе **Go 1.23**, **Wails v2**, **Svelte 5** и **Tailwind v4**.

При работе с проектом **СТРОГО** соблюдайте следующие правила:

---

## 1. Система версионирования (Semantic Versioning)
- **Единый источник правды для версии**: пакет `internal/version/version.go` (`const Version = "X.Y.Z"`).
- Метод `GetAppInfo()` в `internal/desktop/app.go` возвращает эту версию, а интерфейс (`frontend/src/lib/components/layout/Header.svelte`) отображает её в шапке.
- Синхронно обновляйте `"version"` в `frontend/package.json` и константу `VERSION` в `Makefile`.
- **Правила инкремента версии (бампа)**:
  - **PATCH (`X.Y.Z+1`)**: мелкие исправления багов, точечные правки стилей, опечатки в текстах.
  - **MINOR (`X.Y+1.0`)**: добавление нового функционала, новых форматов файлов, переработка экранов UI, оптимизация производительности, обновление мажорных библиотек (например, переход на Svelte 5).
  - **MAJOR (`X+1.0.0`)**: несовместимые изменения формата ключей `.depmap` или фундаментальная смена архитектуры.

---

## 2. Обязательное ведение `CHANGELOG.md`
- Все пользовательские и архитектурные изменения должны фиксироваться в файле `CHANGELOG.md` (в формате [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/)).
- Каждая новая версия должна содержать разделы:
  - `### Добавлено` — новые функции и возможности;
  - `### Изменено` — изменения в существующем поведении, интерфейсе или компонентах;
  - `### Исправлено` — устраненные ошибки и баги;
  - `### Удалено` — удаленный устаревший функционал.

---

## 3. Актуализация документации
- При любом изменении поведения, интерфейса или логики приложения **ОБЯЗАТЕЛЬНО** актуализируйте:
  - `docs/USER_GUIDE.md`: пошаговые инструкции, описание элементов управления, терминологию («ключ шифрования», а не «соль/ключ целостности»).
  - `docs/ARCHITECTURE.md`: описание слоев сервиса, моделей, протоколов, криптографии и реактивного состояния Svelte 5.
  - `README.md`: список форматов, ключевые возможности, бейджи версий.

---

## 4. Требования к безопасности и кодовой базе
- **100% Air-Gapped**: Приложение работает в изолированном контуре. Запрещены любые внешние HTTP/WebSocket запросы, обращение к внешним CDN, сбор метрик или телеметрии.
- **Go Vendor**: Все внешние зависимости Go завендорены в директории `vendor/`. При сборке всегда используется флаг `-mod=vendor`.
- **Криптография**: Ключи `.depmap` шифруются исключительно AES-256-GCM с PBKDF2-HMAC-SHA256 (100 000 итераций).
- **Проверка качества**: После любых правок обязателен прогон:
  - `npm --prefix frontend run check` (проверка типов TypeScript/Svelte)
  - `npm --prefix frontend run build` (сборка бандла фронтенда)
  - `go test ./...` (прохождение всех тестов Go)

---

## 5. Обязательная сборка свежих бинарников (Build Artifacts)
- После любых правок, изменений функционала или исправления багов **ОБЯЗАТЕЛЬНО** пересобирать свежие исполняемые бинарные файлы приложения для поддерживаемых платформ (macOS, Windows, Alt Linux) с помещением их в каталог `bin/`.
- Выполнять сборку через команды:
  - `make build-windows` (или `GOOS=windows GOARCH=amd64 go build ...`)
  - `make build-macos` (или Universal ARM64+Intel)
  - `make build-altlinux` (при наличии Docker)
