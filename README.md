Автономное кроссплатформенное приложение с графическим интерфейсом для автоматического поиска, деперсонализации и **обратного восстановления (деобезличивания)** персональных данных в электронных таблицах (Excel `.xlsx`, `.xlsb`, `.xls`, OpenDocument `.ods`, `.xods`, `.csv`), текстовых документах (Word `.docx`, OpenDocument `.odt`, простой текст `.txt`) и документах `.pdf` в соответствии с требованиями Федерального закона № 152-ФЗ «О персональных данных» и Приказа Роскомнадзора от 19.06.2025 № 140.

## 📌 Ключевые возможности

- 🛡️ **100% On-Premise / Air-Gapped**: Данные не покидают рабочую станцию. Полное отсутствие внешних сетевых вызовов, трекеров, телеметрии и внешних CDN.
- 🤖 **DLP-Safe семантические токены для нейросетей и подрядчиков**:
  - Генерация уникальных типизированных токенов `[ФИО_0001]`, `[Паспорт_0001]`, `[СНИЛС_0001]`, `[Телефон_0001]` и др.
  - **100% обход корпоративных DLP-систем и шлюзов**: токены не содержат цифровых паттернов документов РФ и словарных фамилий, исключая блокировки при отправке файлов в облачные LLM (Claude, ChatGPT, Gemini).
  - Поддержка ссылочной связности данных внутри документа для агрегации и группировки строк нейросетями.
- ⚡ **Бескоординатный механизм обратного восстановления (Coordinate-Free Engine)**:
  - Точное восстановление исходных данных даже при сортировке строк или перемешивании порядка записей нейросетью.
  - Распознавание и восстановление токенов внутри текстовых комментариев и выводов LLM (например: `«Премировать [ФИО_0001]»` -> `«Премировать Иванов Иван Иванович»`).
- ✂️ **Три стратегии обработки: «Для нейросетей», «Синтетика» и «Удаление»**:
  - **Для нейросетей (по умолчанию)**: DLP-Safe токены с бескоординатным восстановлением.
  - **Синтетика**: детерминированная подстановка реалистичных синтетических профилей с валидными контрольными суммами (СНИЛС, ИНН, карты МИР) и сохранением ссылочной целостности через криптосоль.
  - **Удаление**: гарантированная подстановка маркера `[УДАЛЕНО]` на место конфиденциальных данных.
  - Мгновенное переключение стратегий прямо в панели управления с динамическим обновлением предпросмотра таблиц и документов.
- 🔄 **Двусторонняя деперсонализация и устойчивость к LLM (Header-Aware Restoration)**:
  - Формирование зашифрованного файла-ключа **`.depmap`** при сохранении обработанного файла.
  - Возможность вернуть исходные ФИО, паспорта, СНИЛС после разметки подрядчиками или обработки в ML-моделях.
  - **Header-Aware механизм сопоставления**: ключ `.depmap` сохраняет канонические имена целевых колонок (`TargetHeaders`) и точечные координаты ячеек (`CellMappings`). При добавлении внешними нейросетями (LLM) новых столбцов (например, `Sentiment`, `Summary`, `AI_Classification`) в произвольные позиции таблицы обратное восстановление точно находит оригинальные столбцы по именам заголовков, предотвращая порчу данных при сдвиге колонок.
  - **Порядковое восстановление (`OrdinalMappings`)**: надежное восстановление текстовых документов в режиме удаления.
  - **Полное сохранение колонок подрядчиков**: новые столбцы (скоринг, сегменты, метрики), формулы и стили оформления остаются нетронутыми.
- 📊 **Полная поддержка офисных табличных форматов (включая Alt Linux и OpenOffice)**:
  - **Excel OpenXML (`.xlsx`)**: современные электронные таблицы с сохранением структуры, формул и оформления.
  - **OpenDocument Spreadsheet (`.ods`)**: нативная поддержка электронных таблиц LibreOffice Calc / OpenOffice Calc / «МойОфис» в Alt Linux без сторонних зависимостей. Прямое обезличивание, обратное восстановление и выбор формата экспорта (`.ods`, `.xlsx`, `.csv`).
  - **Excel Binary (`.xlsb`)**: скоростное чтение тяжелых бинарных книг Excel с конвертацией в современный `.xlsx` и генерацией `.depmap`.
  - **Excel 97–2003 (`.xls`)**: поддержка бинарного формата BIFF8 с конвертацией в современный `.xlsx` и генерацией `.depmap`.
  - **CSV / TSV**: потоковая обработка текстовых файлов с автоопределением разделителя (`,` `;` `\t` `|`) и кодировки (UTF-8, UTF-8 BOM, Windows-1251).
- 📝 **Деперсонализация текстовых документов (Word и OpenOffice)**:
  - **Microsoft Word (`.docx`)** и **OpenDocument Text (`.odt`)**: деперсонализация параграфов, заголовков, колонтитулов и ячеек таблиц.
  - **Интерактивный Word-предпросмотр с форматированием таблиц**: структурированное отображение таблиц и параграфов на стилизованном листе А4, подсветка маркером заменённых данных, навигация «Назад/Вперёд» и интерактивное переключение деперсонализации по клику на любой фрагмент ПДн прямо в тексте или ячейках таблиц.
  - **Преодоление Run-Splitting**: корректное обнаружение сущностей ПДн, разбитых текстовыми редакторами на множество смежных тегов (`<w:r><w:t>` в Word, `<text:span>` в OpenOffice).
  - **100% сохранение верстки**: цвета, шрифты, стили, поля, изображения, формулы и нечувствительный текст сохраняются байт-в-байт.
  - **Интерактивные сниппеты «до / после»**: предпросмотр фрагментов текста в интерфейсе с бейджами категорий ПДн.
  - **Управление категориями**: возможность выборочно отключать маскирование конкретных категорий данных (например, отключить маскирование дат или телефонов).
  - **Обратное восстановление**: однопроходное нескачкообразное восстановление исходного текста по ключу `.depmap` с защитой от коллизий.
  - **Гибкий экспорт**: выбор выходного формата (`.docx` или `.odt`).
- 📋 **Локальный журнал учета операций (Приказ Роскомнадзора от 19.06.2025 № 140)**:
  - Автоматическая фиксация каждого факта деперсонализации и деобезличивания в структурированном журнале `audit.jsonl` в директории данных приложения (`~/.depersonalizer/audit.jsonl`).
  - Расчет криптографических контрольных сумм исходных и результирующих файлов (SHA-256), фиксация временных меток, статусов и числа обработанных записей.
  - Нативное модальное окно просмотра журнала в интерфейсе (кнопка «Журнал» в шапке) и экспорт полного реестра в файл `.jsonl` для контролирующих органов.
- 🔀 **Перемешивание порядка строк (Shuffling)**:
  - Опциональное криптостойкое перемешивание порядка строк в электронных таблицах (`.xlsx`, `.ods`, `.csv`) по алгоритму Фишера-Йетса для защиты от косвенной деанонимизации по исходному порядку следования записей (п. 13 Приказа РКН № 140).
- 🔐 **Криптографическая стойкость ключа и политика надежности паролей**:
  - Архитектура криптопровайдера `CipherProvider` (`AES256GCMProvider`) с защитой от подделки и модификации (AEAD).
  - Формирование ключа через **PBKDF2-HMAC-SHA256 (100 000 итераций)** с уникальной солью (16 байт) и nonce (12 байт).
  - **Строгая политика надежности паролей**: валидация минимальной длины (не менее 12 символов), ограничение набора строго латиницей (`A-Z`, `a-z`), цифрами и специальными символами во избежание опечаток, проблем с раскладками клавиатуры и визуально схожими буквами (гомоглифами).
  - **Интерактивный контроль в UI**: 4-сегментный цветной индикатор надежности, чеклист критериев (включая проверку «Только латиница»), кнопка переключения видимости (👁) и блокировка сохранения при слабом пароле.
  - **Криптостойкий генератор**: автоматическая генерация 16-значного стойкого случайного пароля со всеми классами символов.
  - Права доступа к файлу ключа на уровне ОС: `0600` (`-rw-------`).
- 🇷🇺 **Полный охват категорий ПДн РФ**:
  - **ФИО целиком или раздельно**: поддержка полного ФИО в одной колонке, а также раздельных колонок (**Фамилия**, **Имя**, **Отчество**) с сохранением пола. Исключение неперсональных сущностей (штатное расписание, структурные единицы).
  - **Адреса и местоположение (ADDRESS)**: адреса регистрации, проживания, города и регионы РФ.
  - **Грейды (GRADE)**: грейды должностей и разряды.
  - **Табельные номера (EMPLOYEE_ID)**: персональные табельные номера сотрудников (`Таб. №`).
  - **Электронная почта (E-mail)**: определение как по заголовкам колонок, так и по контенту строк (включая логины и учетные записи вида `login@domain.ru`).
  - **СНИЛС** с расчётом валидной контрольной суммы по модулю 101.
  - **ИНН физических лиц** (12 знаков) с расчётом двух официальных контрольных сумм ФНС.
  - **Паспорта РФ** (4 цифры серии с кодом региона + 6 цифр номера).
  - **Номера телефонов** РФ (`+7 (9xx) xxx-xx-xx`).
  - **Банковские карты «МИР»** (префикс `2200` с валидным алгоритмом Луна).
  - **Даты рождения и выдачи документов** (сохранение года и реалистичный сдвиг $\pm N$ дней).
- 🔗 **Ссылочная целостность (Referential Integrity)**:
  - Детерминированная псевдонимизация на базе `HMAC-SHA256(значение, соль)`: одинаковые клиенты в разных строках и таблицах получают одинаковые синтетические значения.
- 📑 **Умный анализ таблиц**:
  - **Многостраничные книги Excel и OpenOffice (Multi-Sheet)**: полноценная поддержка книг с несколькими листами: навигационные вкладки листов в основном интерфейсе и полноэкранном окне, раздельная настройка колонок по каждому листу, пакетное обезличивание всех листов в единый файл и сквозное восстановление через `.depmap`.
  - Автоматический поиск шапки таблицы при наличии пустых строк или преамбул выгрузки.
  - Автоматический расчет комфортной ширины столбцов под длину текста заголовков и бейджей `[ ПДн: Замена ]`.
  - Возможность выборочного отключения замены для любых колонок тумблером на карточке или кликом в шапке.
  - Интерактивное масштабирование ширины столбцов (вплоть до компактного вида с обрезкой текста `...`).
  - Полноэкранный предпросмотр с **динамической бесконечной подгрузкой строк** для всех табличных форматов (`.xlsx`, `.xls`, `.xlsb`, `.ods`, `.csv`) порциями по 30 строк без нагрузки на память.
- ⬛ **Blackout Redaction для PDF**:
  - Физическое удаление символов из контентного потока PDF (текст невозможно скопировать или извлечь).
  - Наложение непрозрачных векторных рамок `[ ПДн СКРЫТО ]`.
- 🖱️ **Эргономичный UX**:
  - Адаптивный интерфейс: автоматическое переключение вида для таблиц (сетка колонок, предпросмотр строк) и текстовых документов (карточки категорий, сниппеты «до / после»).
  - Умный Drag & Drop (перетаскивание `.depmap` автоматически активирует режим восстановления).
  - Живой прогресс-бар с замером времени и отображением обработанных строк/ячеек.
  - Быстрое копирование пути к ключу («📋 Копировать ключ») и переход к файлам в проводнике («📁 Показать в папке»).

## 📖 Сценарии использования

### 1. Деперсонализация таблиц (.xlsx, .ods, .xlsb, .xls, .csv)
1. Откройте таблицу любого поддерживаемого формата через кнопку **«Открыть файл...»** или перетащите в окно.
2. Программа определит шапку, типы листов и категории ПДн. Если какую-то колонку нужно оставить без изменений — отключите её тумблером на карточке.
3. Нажмите **«💾 Сохранить обработанный файл»**.
4. В модальном окне выберите формат экспорта (для `.ods` доступны `.ods`, `.xlsx`, `.csv`; для бинарных `.xls` и `.xlsb` сохранение производится в современный `.xlsx`).
5. Оставьте активным чекбокс **«Создать защищенный ключ восстановления (.depmap)»** и при необходимости укажите пароль.
6. Нажмите «Выбрать путь и сохранить». Программа создаст очищенную таблицу и файл-ключ `.depmap`.
7. Очищенную таблицу можно безопасно передавать внешним аналитикам или подрядчикам.

### 2. Деперсонализация текстовых документов (.docx, .odt)
1. Откройте документ Microsoft Word (`.docx`) или OpenDocument Text (`.odt`).
2. Программа автоматически проанализирует параграфы и отобразит карточки категорий найденных ПДн (ФИО, паспорта, контакты, даты и др.) с количеством вхождений.
3. При необходимости отключите определенные типы сущностей кликом по бейджу.
4. В блоке предпросмотра оцените сниппеты с переключением «До деперсонализации» / «После деперсонализации».
5. Нажмите **«💾 Сохранить обработанный файл»**, выберите желаемый выходной формат (`.docx` или `.odt`) и путь сохранения ключа `.depmap`.
6. Текстовый документ сохранит 100% верстки, стилей и структуры, при этом все персональные данные будут заменены на валидные синтетические значения.

### 3. Обратное восстановление данных (деобезличивание)
1. Переключитесь на вкладку **«○ Восстановление данных»** (или просто перетащите файл ключа `.depmap` в окно программы).
2. **Шаг 1**: Выберите возвращенный подрядчиками файл таблицы или текстового документа.
3. **Шаг 2**: Выберите файл-ключ `.depmap`. Программа проверит криптографическую целостность и покажет исходное имя файла и число записей.
4. **Шаг 3**: Введите пароль (если задавался при сохранении).
5. Нажмите **«🔓 Восстановить исходные данные...»**.
6. Исходные персональные данные вернутся на свои места 1-в-1, а добавленные аналитиками новые столбцы и формулы сохранятся в полном объёме.

## 🛠️ Сборка из исходников

Для сборки требуются **Go 1.23+**, **Node.js 18+** (с npm, для компиляции Svelte 5 фронтенда), компилятор C (для сборки CGO под macOS/Linux) и Docker (для сборки под Alt Linux). Все зависимости Go завендорены в директории `vendor/` для полной автономности (Air-Gapped).

Фронтенд автоматически собирается через Vite перед компиляцией исполняемых файлов Go при вызове команд `make`.

### Сборка под все платформы сразу:
```bash
make build-all
```

### Сборка под Alt Linux 10.4 (в нативном Docker alt:p10):
```bash
make build-altlinux
```

### Сборка под macOS Universal (ARM64 + Intel):
```bash
make build-macos
```

### Сборка под Windows (x86_64):
```bash
make build-windows
```

### Сборка только фронтенда:
```bash
make build-frontend
```

### Запуск тестов:
```bash
make test
```
